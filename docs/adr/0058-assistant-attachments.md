# ADR-0058: 어시스턴트 창에 끌어다 놓은 그림·파일·폴더를 그 대화의 첨부로 붙인다 — 파일·폴더는 읽기 전용으로 허락하고, 그림은 기록 옆 폴더에 줄여 두고 말마다 최근 5장을 다시 보낸다

- 상태: Proposed
- 날짜: 2026-11-17
- 관련: ADR-0031(대화 기록), ADR-0057(ACP 에이전트) · `src/agent/attach.rs`(첨부·그림 저장·허락), `src/agent/mod.rs`(`Turn::attachments`, `request_turns`), `src/agent/tools.rs`(`Workspace::with_grants`), `src/agent/bedrock.rs`(`user_message`), `src/agent/acp/mod.rs`(첨부 → ACP 블록), `src/agent/acp/adapter.rs`(`Input`), `src/agent/acp/claude.rs`(`Attached`), `src/agent/acp/codex.rs`(`Readable`, `localImage`), `src/agent/history.rs`(첨부 폴더), `src/app/assistant_panel.rs`(드롭·칩·썸네일)

## 배경 (Context)

- 어시스턴트는 라이브러리 안만 읽는다. 내장 도구는 라이브러리 기준 상대 경로만 받고, Claude Code는 `--restricted`로 작업 폴더 안에 갇히며, Codex는 라이브러리 안의 읽기 명령만 허락한다. 라이브러리 밖의 자료(참고 문서, 스크린샷)를 보이려면 내용을 복사해 붙여야 했다.
- 대화를 보낼 때마다 `Turn` 목록으로 대화를 새로 만든다(내장 제공자는 `Message::user(&turn.text)`, 에이전트는 앞의 말을 글 하나로 묶는다). 그래서 그림을 첨부한 말에서만 보내면, 창을 닫지 않아도 다음 말부터 모델이 그림을 잃는다. 대화를 다시 열어도 마찬가지다.
- 그림 바이트는 보낼 때 API로만 가고 앱에 남지 않는다. 대화 내역에 그림을 다시 그리고 모델에 다시 보내려면 어딘가에 남겨야 한다.

## 결정 (Decision)

**어시스턴트 패널에 끌어다 놓거나(Finder에서 복사해 붙여 넣어도) 다음 말의 첨부로 붙인다.** 입력창 위에 칩(그림은 이름, 파일·폴더는 아이콘과 이름)으로 보이고 ×로 뺀다. 첨부만 있으면 글이 없어도 보낼 수 있다. 첨부는 `Turn::attachments`에 종류(그림·파일·폴더), 원래 경로(실제 경로), 그림이면 저장한 파일 이름으로 적는다.

**파일·폴더는 경로만 적고, 그 대화에서는 읽기 전용으로 허락한다.** 허락 목록은 대화의 첨부에서 바로 구한다(`attach::grants`). 따로 저장하지 않아도 대화를 다시 열면 이어진다. 모델에는 사용자 말 끝에 `[The user attached the following …]`로 절대 경로를 알린다. 허락 검사는 실제 경로(`canonicalize`)로 해서 링크·`..`로 벗어나지 못한다.

| 제공자 | 읽기 | 쓰기 |
| --- | --- | --- |
| 내장(Bedrock·Token Plan) | `read_file`·`list_files`가 허락한 경로 안의 절대 경로도 받는다. 허락한 폴더 안의 숨김 항목은 거부한다 | 라이브러리 안만(바뀌지 않음) |
| Claude Code | 폴더는 `--add-dir`로 연다. 파일은 200KB 이하 텍스트면 내용을 `<attached_file>`로 메시지에 넣고, 크거나 텍스트가 아니면 상위 폴더를 `--add-dir`로 연다(파일 하나 때문에 폴더를 열지 않으려고) | `can_use_tool`에서 라이브러리 밖이면 묻지 않고 거절한다(`--add-dir`이 쓰기도 열기 때문) |
| Codex | 읽기 명령 허락 검사(`read_only_in`·`read_only_argv`)가 허락한 경로도 받는다. 지시도 "라이브러리 또는 붙인 경로"로 바꿨다 | 파일 변경 승인 요청이 라이브러리 밖이면 묻지 않고 거절한다 |

**그림은 보낼 때 모델이 받는 크기(긴 변 1568px, `web::prepare_image`)로 줄여 대화 기록 옆 첨부 폴더에 쓴다.** 위치는 `<data_dir>/Hanji/<라이브러리 키>/attachments/<대화 id>/<내용 해시>.<확장자>`다. 기록 번호가 아직 없는 새 대화면 보낼 때 번호를 준다. 대화 내역의 썸네일도 이 파일을 그린다. 원본을 옮기거나 지워도 대화에는 남는다. 기록을 열지 못하면 원래 파일을 읽는다.

- 이름은 내용 해시라서 같은 그림을 다시 붙여도 한 벌만 남고, 말이 잘린 뒤 같은 순번에 다른 말이 와도 겹치지 않는다.
- 대화를 지우면 기록을 먼저 지우고 대화 폴더를 지운다. 말이 잘리면(고쳐 다시 보내기) `save` 뒤에 어느 말에도 없는 파일을 지운다. 기록을 열 때는 기록에 없는 대화의 폴더를 지운다(중간에 앱이 꺼졌을 때).
- redb 안에 바이트를 두지 않은 까닭: redb는 지운 만큼 파일이 줄지 않고, Codex(`localImage`)와 썸네일은 파일 경로를 바로 쓴다.

**그림은 말마다 다시 보낸다. 최근 5장(`attach::MAX_IMAGES`)만 보내고, 그보다 앞의 그림은 이름만 알린다.** 내장 제공자는 사용자 메시지에 이미지 블록으로 넣고(그림을 못 보는 Token Plan 모델이면 알림 글), 에이전트에는 ACP 이미지 블록(내용은 base64, 파일 경로는 `uri`)으로 넘긴다. Claude Code는 stream-json 사용자 메시지의 이미지 블록으로, Codex는 `localImage`(경로)로 바꾼다.

## 결과 (Consequences)

- 좋아지는 점(+): 라이브러리 밖의 자료를 복사하지 않고 보일 수 있다. 세 제공자가 같은 첨부를 같은 뜻으로 받는다(실제 CLI·Bedrock으로 붙인 파일·폴더 안 파일·그림을 모두 읽는 것을 확인했다: `acp::live`의 `*_attachments`). 그림은 대화를 다시 열어도 모델과 화면에 남는다.
- 감수하는 점(-): 그림을 말마다 다시 보내 토큰이 든다(한 장에 대략 1~2천 토큰). 내장 제공자는 프롬프트 캐시로 대부분 줄지만, 에이전트는 말마다 새 프로세스라 덜하다. 그림을 보낼 때 줄이는 일을 화면 스레드에서 해서, 큰 그림이면 보낼 때 잠깐 멈출 수 있다. Claude Code에 붙인 작은 파일은 말마다 내용이 다시 들어간다. 큰 파일 하나를 붙이면 그 상위 폴더 전체가 Claude Code에 열린다(읽기만).
- 원래 파일·폴더를 옮기거나 지우면 그 경로는 더 읽지 못하고 칩에 "(파일 없음)"이 붙는다. 그림은 첨부 폴더에 남아 있다.
- 후속 작업(TODO): 그림 줄이기를 백그라운드로. 라이브러리 없이 쓰는 내장 제공자(도구 없음)에서 작은 파일 내용 넣기. 대화 중 허락을 거두기.

## 대안 (Alternatives)

| 대안 | 기각 사유 |
| --- | --- |
| 첨부한 말에서만 그림을 보내고 다음부터는 경로로 다시 읽게 하기 | 다음 말부터 모델이 그림을 잃는다. 원본이 그대로 있고 모델이 스스로 읽으려 할 때만 통한다 |
| 그림 바이트를 같은 redb에 표로 두기 | 지워도 파일이 줄지 않아(`compact` 필요) 크고 자주 지우는 데이터에 맞지 않고, Codex에 넘길 때 임시 파일로 꺼내야 한다 |
| 그림은 경로만 적기 | 원본을 옮기거나 지우면 대화 내역에서도 모델에서도 사라진다 |
| 파일 내용을 늘 메시지에 붙이기 | 폴더나 큰 파일이면 맥락이 넘친다. Claude Code의 작은 텍스트 파일만 그렇게 한다 |
| 설정에 "항상 허용할 폴더" 목록 | 모든 대화에 범위가 열린다. 필요하면 나중에 더한다 |
| Claude Code에 파일 하나도 상위 폴더를 `--add-dir`로 열기 | 끌어다 놓은 파일 하나 때문에 같은 폴더의 다른 파일까지 열린다 |
